# 插件 EDSL:按构造满足组件义务(设计草案)

目标:提供一个写插件的嵌入式语言,由它生成 Cordis 插件的 JS 代码,使组件义务(`Summary.v` 的
有界、有秩、相遇受控、完整提供,以及 PLUGIN-AUDIT 的 S1–S3、L1、R1–R2，即上一轮的 (a)–(e))随构造成立,或在编译期、链接期检查。

本文只做设计,不含证明与实现。服务一侧沿用 OPLIB.md 的贡献模型,本文讨论插件一侧。

## 1. 动机

PLUGIN-AUDIT 的结论是:差距主要在"Cordis 允许什么"与"Cordis 保证什么"之间,改进方向是把隐含的纪律
写成义务并强制执行,让"按 Cordis 的方式写"与"满足模型"成为同一件事。lint 与 EDSL 是强制执行的两种方式:

| | lint | EDSL |
|---|---|---|
| 作用对象 | 现有的 TS 插件 | 新写或改写的插件 |
| 能做到的 | 找 bug | 义务按构造成立 |
| 代价 | 只能近似,漏报误报都有 | 要重写,表达力受限 |

两者互补。本文只讨论 EDSL。

真正起作用的不是"生成 JS",而是**程序在激活之前是一份数据**,可以被分析、被不同地解释。

## 2. 分层与可信基

```
插件源码 (EDSL)
   │  多个解释
   ├─→ JS 生成器 ──→ 生成的插件 ──→ 垫片 (rt) ──→ Cordis
   ├─→ 演算执行器 (proto 的随机调度器)
   ├─→ 静态分析 (键集、ops_k、有界、完整提供)
   └─→ 初始 AST (与 Rocq 的 Prog 对应)
```

生成的代码不直接调用 Cordis 原语,而是调用一个薄的运行时垫片 `rt`。原因是 Cordis 的语义与演算不同:

| Cordis | 演算 | 垫片的做法 |
|---|---|---|
| `Promise.all` 并发执行 disposer | LIFO 串行撤销 | 串行、逆序执行撤销栈 |
| 按回调身份注销 | 按令牌撤回 | `put` 返回按令牌撤回的 disposer |
| 启动函数中可以任意 `await` | 每个服务操作是原子步 | 操作内部不 `await`,只在操作之间 |
| `ctx.get` 可读任意服务 | 只能访问 d ∪ p | 只暴露声明过的键 |

可信基 = 垫片 + JS 生成器。两者都要尽量小。

## 3. 语言的形式

### 3.1 tagless final

插件写在一个抽象签名上,每种用途是一个解释。需要的解释至少有:

1. **JS 生成**:输出调用 `rt` 的代码;
2. **演算执行**:在 proto 的调度器里运行,用于差分测试;
3. **静态分析**:键集、每个键上的操作集 `ops_k`(判断相遇要用)、有界、完整提供;
4. **初始 AST**:生成与 Rocq `Prog` 一一对应的结构;
5. 文档、美化打印。

给某个服务加专用操作只需扩展签名。

### 3.2 关键约束:结果只能在对象语言中检查

不论 initial 还是 final 编码,只要续延是宿主闭包、能在宿主层面对操作结果做 `if`,分析解释器就看不到这个分支,
无法枚举到达 `Done` 的路径。所以:

- 操作结果的类型是 `repr`,宿主只能把它传给对象语言的组合子;
- 分支是签名中的方法(`if/r`、`case/r`):分析时走两边,生成 JS 时输出 `if`,执行时求值;
- 续延用 HOAS 写:`(bind (read cfg) (λ (c) ...))` 中的 `c` 在分析器中是符号,在生成器中是 JS 表达式,
  在执行器中是实际值。

这把"程序看不到状态,只能根据结果分支"变成语言层面的约束。贡献模型下分支的来源只有 F 与静态数据
(`Put` 没有结果,`Read` 读的是常量 F),所以路径枚举很便宜。

### 3.3 与 Rocq 的对应

tagless final 的程序是 `Prog` 的 Church 编码。在 Rocq 中可以把签名写成 record,`Prog` 是它的初始代数;
Racket 一侧的"初始 AST"解释就是这个初始代数。于是 Racket 中写 final、Rocq 中证 initial,
中间需要的桥只有这一个解释。

## 4. 宿主语言

### 4.1 Racket 的做法

tagless final 在 Haskell/OCaml 中由类型检查保证对象语言良类型。Racket 没有,Typed Racket 缺高阶类型,
抽象不了 `repr`。改用 Racket 自己的机制:

1. **语义**:字典传递,一个解释是实现签名方法的结构体,程序是 `(λ (S) ...)`(或用 parameter 隐式传递)。
2. **纪律**:`#lang cordis` 只导出组合子,插件模块拿不到 Racket 的 `if`、`set!`、`require`,
   宿主层面的检查写不出来。语言限制代替类型。
3. **声明与静态检查**:`define-plugin` 宏在展开期检查 `#:inject`/`#:provide` 与程序中用到的键一致,
   报错指向源码位置。

```racket
#lang cordis
(define-plugin pet
  #:inject (tools config)
  #:provide (pet-api)
  (provide pet-api (js "./api-init.js"))
  (bind (read config)
        (λ (cfg)
          (if/r (field cfg 'enabled)
                (put tools (tool "pet" #:exec (js "./exec.js")))
                (done)))))
```

### 4.2 与 Haskell/OCaml 的比较

| | Racket | Haskell/OCaml |
|---|---|---|
| 程序检查不了结果 | 语言限制,工程上的封闭,漏导出一个绑定就破 | 参数性,`forall repr. Sym repr => repr a` 的 free theorem;OCaml 中多态相等是漏洞,见 10.2 |
| 键集 k ∈ d ∪ p | 展开期检查 | 放进类型:OCaml 多态变体 ``[< `Tools \| `Config ]``;Haskell 的 indexed monad 还能跟踪已提供的键 |
| 完整提供 | 展开期枚举路径 | 可做成类型检查(代价高) |
| 有秩、相遇受控 | 链接期 | 链接期(全局性质,进不了类型) |
| 报错 | 完全可定制 | 类型层编码的报错难读 |
| 表层语法 | 自由 | 受限 |
| 生成 JS | quasiquote 构造 JS AST | 需要另写 |
| 现有代码 | `programs/cordis*.rkt` 的调度器可直接复用 | 无 |
| 验证运行时 | 无 | Rocq 抽取到 OCaml,再经 Melange 或 js_of_ocaml 到 JS |

最后一行是 OCaml 最强的理由:演算的解释器(LIFO 撤销、按令牌撤回、`target` 追赶)可以在 Rocq 中写和证,
再抽取成 JS 运行时,可信基中最微妙的部分从手写变成抽取。这条路原则上可行,但抽取代码中的 `Obj.magic`、
性能、与 Cordis 的 Promise 接口对接都要实测。

**决定(暂定)**:两步走。先用 Racket 定签名与表层语言(便宜,复用 proto);签名稳定后,把运行时放到
Rocq → OCaml → JS 上。插件 EDSL 是否迁到 OCaml,看抽取路线是否走通再定。签名本身与宿主语言无关,
迁移成本主要在表层语法与展开期检查。

## 5. 义务如何保证

| 义务 / 审计项 | 保证方式 | 时机 |
|---|---|---|
| (a)(b) 访问的键在 d ∪ p 中,p 静态 | `inject`/`provide` 元数据由程序生成;`ctx` 只暴露声明的键 | 构造 |
| 有界 | 启动程序中没有一般递归;宿主层的循环在生成时展开 | 构造 |
| 相遇受控 | 只有 `Read`/`Put`,G 取全关系 | 构造 |
| 完整提供 | 枚举到达 `Done` 的路径 | 编译期 |
| (d) 效应都登记在 fiber 上 | 只生成经 `rt` 登记的调用;资源用 `resource`(第 6 节) | 构造 |
| (e) 反应用子 fiber 承载 | `on` 处理器编译成子 fiber(`O-React`) | 构造 |
| 有秩 | 对整张组件表检查依赖与 spawn 无环;混入手写 JS 插件时只覆盖 EDSL 部分 | 链接期 |

### 5.1 载荷

业务逻辑(工具的 `execute`、路由处理器)是不透明的 JS 载荷 `(js "...")`:生成器原样嵌入,执行器换成
Racket 桩,分析器当作未知。载荷若捕获 `ctx`、碰 `globalThis` 或模块级状态,保证就漏了。JS 无法强制隔离,
所以保证的形式是**载荷满足纪律时成立**:

- 载荷收到受限的能力对象,不收到 `ctx`;
- 启动代码中读到的值(如 F 中的配置)以函数参数传给载荷,不经闭包或全局变量;
- lint 检查载荷文件不引用 `ctx`、`globalThis`,没有模块级可变状态。

外部持久世界(文件、凭据、配置文件)不在定理范围内(审计结论 3)。

### 5.2 与外部世界的边界

演算的性质(合流、恢复精确、级联卸载)说的是受管状态 S:绑定、贡献多重集、fiber。外部世界不在 S 中,
所以和外部交互之后,性质变成**相对于载荷义务**的:外部一侧满足义务时性质成立,与总结定理把服务规格当作
假设是同一种结构。插件与外部只有四条通道:

| 通道 | 方向 | 演算还保证什么 | 前提 |
|---|---|---|---|
| 事件 `on`/`emit` | 外 → 内 | 全部:反应是子 fiber,效应入栈,随父撤销 | 无;终态依赖事件序列,合流指给定输入时与调度无关 |
| 资源 `resource` | 内 → 外,加载时 | 恢复精确延伸到外部世界 | `release` 确实是 `acquire` 的逆(载荷义务) |
| 载荷闭包 `js` | 内 → 外,调用时 | 卸载后闭包作废,调不到 | 闭包运行时做什么不归演算管;它发起的异步工作卸载后是否停止,也不管 |
| 读外部状态 | 外 → 内 | 语言中没有这个原语 | 由边界插件把外部来源提供为一个键(如 `config`),外部变化即重新 provide,依赖者按 L 规则重载 |

原型最初有两个漏洞,现已补上(`rt.js`):

1. **载荷在加载时运行。** `(js p e …)` 原先编译成 `payload(p)(e …)`,工厂在加载时被调用,它的效应不入撤销栈,
   结果还能经 `eq` 进入 `if`,外部世界因此能影响控制流。现在编译成 `I.lazy(p, [e …])`:加载时只求值参数
   (都是 S 中的数据),连 `require` 都不做;宿主第一次调用闭包时才构造。加载期间载荷效应为零,
   对这个值做条件判断只能得到常量(函数恒为真,`===` 恒为假)。所以不需要在类型上把载荷值与普通值分开。
2. **卸载后闭包还能用。** 撤回 put 只是把贡献从 C 中删去,宿主若缓存了 `exec` 照样能调用。现在 put 与
   provide 的值里的函数都包上可撤销的包装(`seal`),撤销对应的操作时作废,之后调用即抛 `revoked`。
   重新加载产生新的闭包,旧的不会复活。经别的插件转手贡献的函数会再包一层,任一层作废即作废。

`resource` 的载荷模块在加载时 `require`,模块顶层代码会运行;这属于 `acquire` 的一部分,由同一条义务覆盖。
信任基于是成为:垫片 + 生成器 + 载荷,载荷的义务是**工厂与模块顶层无外部效应、`release` 逆 `acquire`**。
剩下演算说不了的只有闭包本身做得对不对,那本不是生命周期演算的事。调用期的效应若需要管理(如 `exec` 启动子进程),
下一步是给闭包一个随插件卸载而关闭的作用域,在其中获取的资源一并释放;尚未实现。

## 6. 表达力

对照 PLUGIN-AUDIT 上一轮的 6 个插件 (本轮扩充到 26 个，结论见该文档)。

### 6.1 已经能表达的

- 登记类扩展:工具、路由、slot、监听器、`tools.restrict`、覆盖写配置,都是带优先级的 `Put`(OPLIB 第 5 节);
- 提供者的配置给依赖者读:F 与 `Read`;
- 按功能拆分的子 fiber:dsh-context 的 `watch*Channel` 即带依赖的 `Spawn`;
- 运行期反应:子 fiber;
- 业务逻辑:载荷。

### 6.2 缺口(按优先级)

1. **资源原语 `resource`。** 计时器、子进程、裸 disposer 的路由是审计中最常见的 bug(d)。在载荷中成对给出
   acquire/release,登记在 fiber 上,按 LIFO 释放。它作用于外部世界,恢复精确性不覆盖,但保证卸载后不泄漏。
   没有它,EDSL 消不掉最该消掉的那类 bug。
2. **可选依赖。** 6 个插件都有(dsh-context 约 30 处)。没有它,作者只能硬依赖(在缺服务的宿主上停在 PENDING),
   或在载荷里偷偷 `ctx.get`。演算中的扩展:视图 ω 允许可选键取 ⊥,提供者出现或消失时 `target` 改变,
   fiber 重新加载。仍由 `target` 驱动,静态组装在有秩时仍唯一;合流的证明要重做。
3. **带谓词的贡献。** "有 `ls` 才起别名"、按 `desktopProfiles` 选分支这类逻辑,OPLIB 推给 view,但 view 由
   服务作者写,插件需要新的条件时服务未必支持。改为贡献携带纯谓词,如 `(put shell (when-present 'ls alias))`,
   由 view 在最终的多重集上求值。否定("没有 X 时才生效")会产生非单调不动点,需要分层,或只允许正条件。
4. **异步初始化。** 如 dsh-pet 下载 Electron、读文件后再登记。演算中操作是原子步,没有"启动中途 await
   外部 IO"。候选:做成结果不透明的外部读取操作(重放结果可能不同,合流对它不成立,要明说);或要求移到
   Active 期间的反应中。
5. **运行期可变设置。** F 冻结。用户在运行期改设置只能作为反应 `Put`,"最近一次生效"需要时间顺序。
   反应不在合流定理内,这里可以放宽。

### 6.3 刻意不支持

- **交集生命周期**(dsh-ops 把子 fiber 挂到别人的 agent 上):部分可由 view 化解,如 `restrict` 的贡献以 agent
  为键,view 与存活的 agent 做 join;把子插件挂进别人的上下文不支持。
- **编排者**(dshmarket):需要另一套语言与义务。
- **元层**(猴补丁、`internal/get`、`internal/dispatch`):排除。

### 6.4 覆盖面粗估

| 插件 | 现在 | 补上 6.2 的 1–4 之后 |
|---|---|---|
| dsh-windows-mcp | 差资源与可选依赖 | 基本能写,`restrict` 走 view |
| dsh-whale-widget | 差资源 | 能写 |
| dsh-pet | 差可选依赖、子进程、异步下载 | 能写 |
| dsh-context | 可选依赖过多 | 大部分能写,猴补丁除外 |
| dsh-ops | 交集生命周期、运行期设置 | 一部分 |
| dshmarket | 编排者 | 不在范围内 |

## 7. 表达力之外的可用性

- **载荷传参**:见 5.1。必须有明确的通道,否则作者会绕过去。
- **调试**:生成的 JS 带 source map,指回 EDSL 源码。
- **报错**:违反义务时用插件作者的话说,例如"两个插件可能同时登记同名工具",而不是"meet 关系不在 G 内"。
- **采用**:第三方作者写 TS。Racket 版是研究产物;给人用时,同样的约束可以做成 TS 库(类型限制 `ctx` 上的键,
  程序先构造成数据,解释器检查后再激活)。

## 10. 原型(2026-11-19)

代码在 `edsl/`,`sh edsl/check.sh` 在 WSL 中跑全部检查。Racket 与 OCaml 各实现了第 9 节第 1–3 步中的签名、
三个解释(初始 AST、JS 生成、静态分析)和链接期检查,垫片 `rt` 是手写的。示例是 7 个插件,覆盖
贡献、冻结的 F、可选依赖、资源、反应、spawn、有条件生效的贡献(由 view 判断)和同名冲突。

### 10.1 结果

- **两版输出逐字相同**:同一组插件的 AST、JS 和分析报告逐字节相同。签名确实与宿主语言无关;
  迁移的成本只在表层语法和检查方式上。
- **生成的 JS 满足生命周期性质**:在 `rt` 上测试通过以下几项:200 个随机调度(随机安装顺序、
  安装之间随机走若干步)到达同一终态;卸载 pet 等于没装过 pet;可选依赖出现和消失时重新加载;
  反应的效应随父 fiber 撤销;撤走提供者时依赖者级联卸载;全部卸载后资源计数归零;
  加载期间(包括 200 次随机装卸)载荷工厂一次也没被调用;卸载后宿主缓存的闭包调用即抛错(见 5.2)。
- **JS 中程序的形状**:插件体是生成器,每个 `yield` 是一个原子操作,放弃加载就是 `gen.return()`。
  生成器就是 JS 中的 free monad,与 `Prog` 一一对应。`seq` 编译成带标签的块,`done` 编译成 `break`。

### 10.2 两个宿主的比较(实测)

| | Racket | OCaml |
|---|---|---|
| 未声明的键 | 展开期报错,中文信息,指向源码位置 | 类型错误:"does not allow tag(s) `Agents" |
| 反应中 provide | 展开期报错 | 类型错误:反应的 `'p` 是 `no_provide` |
| 宿主层面检查结果 | 写不出来,但报错是 syntax-parse 的通用信息 | 模式匹配写不出来;**多态相等 `=` 能通过类型检查**,只在生成时因比较函数值而抛异常 |
| 完整提供、有秩 | 分析器 | 分析器(与 Racket 相同的报告) |
| 声明列表 ⊆ 键集 | 展开期 | 类型(列表中的键必须在标注里) |
| 键集 ⊆ 声明列表 | 展开期 | 只能靠分析器 |
| 作者的负担 | 无标注 | 每个插件要写键集标注;插件名与键名会互相遮蔽 |

两点是实现时才发现的:

1. **Racket 的解释必须在渲染的整个动态范围内生效。** 续延在渲染时才被调用,如果只在构造 repr 时
   `parameterize` 解释,就会在调用续延时丢掉它。用 parameter 实现字典传递很脆弱;OCaml 的 functor
   在静态上确定了解释,没有这个问题。
2. **OCaml 的参数性有漏洞。** 多态相等、`compare`、`Hashtbl.hash`、`Obj.magic` 对抽象类型都能用,
   所以"程序检查不了结果"不是 free theorem 给出的保证,而是"不用这几个函数"时才成立。目前 repr 恰好是函数,
   误用会在生成时抛异常,但换一种表示(比如字符串)就会悄悄通过。补救办法:在插件模块中遮蔽这几个函数,
   或者用 lint 检查。第 4.2 节表中"参数性"一行要按这一点修正。

另外,OCaml 键的定义需要协变的 `type +'k t`,否则在值限制下 `Key.v "tools"` 不能多态。
dune 在 `/mnt/d` 上建不了 socket,构建目录要放在 Linux 文件系统中。

### 10.3 垫片

写测试时在 `rt` 里发现了一个 bug:`emit` 一边遍历累加器一边往表头插入,于是无限循环。
这说明手写的垫片本身就需要验证,支持第 4.2 节中把运行时改为从 Rocq 抽取的方向。

### 10.4 没有做的

- 垫片不在真实的 Cordis 上运行,`rt` 是一个独立的演算实现。Cordis 适配层还没有写。
- 没有和 proto 的演算解释器做差分测试,测试直接检查 `rt` 上的性质。
- 带谓词的贡献没有进语言,示例中的条件生效靠的是 view 解释贡献中的数据(`when` 字段)。
- 异步初始化、载荷 lint、source map 没有做。载荷义务(5.2)目前没有任何检查。
- 载荷闭包调用期的作用域(卸载时停止它发起的异步工作、释放它获取的资源)没有做。
- Rocq → OCaml → JS 的运行时抽取没有尝试(js_of_ocaml 已装好)。
